# 可选预览页与归档包

只有用户需要网页对比或素材浏览时才制作网页。模板不依赖游戏、引擎、Vite、Node 或网络字体，也不会接入游戏源码。

```text
python SKILL_DIR/scripts/ui_assets.py preview --run RUN_DIR
```

输出 `preview/index.html`、`style.css`、`app.js`、`data.json`。从独立 PNG 按 `instances` 的坐标和层级实时拼装，可拖动比较、左右并排、看原稿/拼装/叠图/差异，控制图层显隐，搜索和筛选素材，查看尺寸、来源、Alpha 检查及生成轮次，下载独立 PNG。

整个任务目录需要能通过 HTTP 访问，不能只移动 preview 子目录。例如：

```text
python -m http.server 8000 --bind 127.0.0.1 --directory RUN_DIR
```

访问 `http://127.0.0.1:8000/preview/`；已有项目静态服务可直接使用其任务目录 URL。不要求占用某个固定端口，不覆盖已有主页。

可以在素材未齐时生成阶段页：缺项显示待生成，错误显示待处理，旧分数不会冒充当前已验收。网页是**生成时快照**，输入、素材更新后运行 `preview --replace`；严格预览在评分更新后用 `preview --mode strict --replace` 刷新；不能把未刷新的已验收页作为当前结果交付。

## 快速模式（默认）

首版需要网页时，直接使用模板，不额外设计网页。将页面与关键图片加载、拼装显示以及一次对比切换和素材查看合并到首版常规检查中，完成后立即交付；不再先检查静态拼装、再检查网页、最后收尾复测。不穷举所有模式、筛选组合和视口。实际故障定向修复，只复查受影响项；有新证据且有进展时继续，停止条件沿用 SKILL.md。

`preview` / `status` 默认 `--mode quick`：只运行一次素材结构检查，不调用 verify，不读取或改写 acceptance.json，不生成评分草稿。即使目录中留有旧评分，也不把它当作当前结论。

| 字段/状态 | 含义 |
|---|---|
| `structural_passed` | 当前素材文件、尺寸、Alpha、来源链和实例检查是否通过 |
| `assets-ready` / `assets-needed` | 快速预览素材结构通过 / 存在待处理项 |
| `strict_review: not-requested` | 本次未运行严格验收，既不表示验收失败，也不表示视觉通过 |
| `accepted` / `review-needed` | 仅严格模式使用，当前验收通过 / 严格证据或评分未达标 |

结构通过、首版交付和严格验收是不同判断：前者由脚本检查，首版还需查看实际产物；严格验收须显式请求。实际缺失或不可用素材仍如实显示。

## 用户要求精修验收时的网页检查

明确要求严格验收时，用 `preview --mode strict` 生成严格状态页。仅要求局部精修可继续使用 quick，无需新增评分。根据本次改动检查受影响的行为；首次严格网页交付确认：

- 所有可用图片加载成功，无控制台错误和 404；拼装使用独立层。
- 切换模式、拖动比例、图层显隐会真实改变画面；搜索/筛选和详情可用。
- 深浅底和棋盘格只在查看器中，下载仍是原始透明 PNG。
- 桌面和窄屏均能操作，长 ID/路径不会撑出横向滚动。
- 状态、素材分类数量、当前审核分数与实际验收一致；不把静态预览称为游戏实现。

## 按需打包

默认交付任务目录或预览链接，不自动打包。用户需要快速首版压缩包时，可普通归档当前素材、清单、来源、拼装与已生成的预览，排除历史、缓存和压缩包自身；不要为打包追加评分，也不声明严格验收通过。

以下 `pack` 命令仍要求严格验收通过，仅用于用户明确要求的严格验收成果：

```text
python SKILL_DIR/scripts/ui_assets.py pack --run RUN_DIR --output delivery/assets.zip
```

工具先验证当前结果，通过后才打正式包。包含独立图片、清单、基准、原始与标准化图、提示词、recipe、蒙版、来源记录、拼装、对照证据，以及已生成的预览页与声明的本地构建输入。解压后应能重建并查看来源，不只交一张合成图。

已有预览必须对应当前验收版本，陈旧快照会阻止严格打包，先重跑 `preview --mode strict --replace`。默认排除 history、缓存、隐藏文件和无关目录，不把 zip 自身装入包。写完会检查 ZIP CRC 与文件清单。已有包可用新版本路径或 `--replace`（先归档旧包）。快速首版可直接交付或普通归档，不使用严格 `pack` 命令绕过评分门槛。
