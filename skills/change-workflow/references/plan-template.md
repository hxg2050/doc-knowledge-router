# 精简变更计划模板

仅在需要落盘计划时使用，优先沿用项目模板和已有计划。删除不相关的内容，不必保留空栏目。

## 目标与边界

用一两句话说明完成后的可见结果，以及必须保留的约束。必要时记录明确不在本次范围内的工作。

## 已确认决策

记录影响后续实施的选择及简短依据。区分已确认结论与待验证假设；发生变化时补充原因，不把过期决策当作不可修改的规则。

## 实施步骤

- [ ] 必要步骤，注明相关模块或文件。
- [ ] 根据实际依赖安排后续步骤。

涉及接口或数据迁移时，按需要补充行为变化、兼容范围和恢复办法。

## 验证与结果

记录需要证明的行为、具体命令或手工检查及实际结果。区分“待执行”“通过”“失败”“环境阻塞”，不要把计划执行当成已经执行。

有结果后注明必要的工作目录、被验证状态和限制；例如相关提交、最终差异、或检查后修改过哪些文件。记录到足以判断旧结果是否仍适用即可。

## 续作记录

在需要交接时更新；已完成的短任务可删除本节。

- **已完成：**已经实现或验证的结果。
- **当前状态：**工作位置、相关未提交改动与必要上下文。
- **阻塞或失败：**实际问题、已尝试的方法及继续所需条件；没有则略去。
- **下一步：**最先要完成的一两个具体动作。

恢复工作时先核对最新要求和工作区变化，再决定哪些记录与验证仍有效。
